IPN vs PayPal Webhooks — which to use?
PayPal supports two notification systems: IPN (legacy, NVP/SOAP API) and Webhooks (REST API, recommended for new integrations). Use IPN if you're using PayPal Standard Payments, Buy Now buttons, or the classic PayPal checkout. Use Webhooks if you're using the PayPal REST API or Orders API. Both support sandbox testing — IPN via the IPN Simulator, Webhooks via the PayPal Developer Dashboard webhook simulator.

Why PayPal returns INVALID when you test locally
PayPal IPN verification posts back to your server — if you're running on localhost, PayPal cannot reach you. Solutions: (1) Use ngrok (ngrok http 3000) to expose your local port. (2) Test IPN handling logic by posting a generated payload directly to your local endpoint with curl (use the generator above). (3) Deploy to a staging server. (4) Use PayPal Sandbox with your real server URL before going to production.

Critical: always verify the IPN before processing
Anyone can POST a fake IPN to your endpoint. Always verify by POSTing the received data back to PayPal's verification URL (ipnpb.paypal.com/cgi-bin/webscr) with cmd=_notify-validate prepended. Only process the payment if PayPal returns VERIFIED. Additional checks: verify payment_status=Completed, verify mc_gross matches your expected price, and verify receiver_email is your PayPal account email.

FAQ — PayPal IPN simulator
PayPal IPN (Instant Payment Notification) is a server-to-server notification system. When a payment event occurs, PayPal sends an HTTP POST to your IPN listener URL with transaction details. Your server responds 200 OK, then verifies by posting the data back to PayPal's verification endpoint. Use IPN for PayPal Standard, Buy Now buttons, and legacy integrations. Use Webhooks for REST API integrations.
(1) ngrok method: run ngrok http 3000, copy the HTTPS URL, set it as your PayPal Sandbox IPN URL, use the PayPal IPN Simulator at developer.paypal.com. (2) Direct POST method: use this generator to create a payload, then curl -X POST http://localhost:3000/ipn -d 'PAYLOAD' — this tests your handler logic without needing PayPal to reach you. (3) Note: the IPN verification step (posting back to PayPal) won't work on localhost — mock it during local testing.
Common causes: (1) Not prepending cmd=_notify-validate& before the raw POST body when verifying. (2) Using production IPN URL (ipnpb.paypal.com) for sandbox — use ipnpb.sandbox.paypal.com for sandbox. (3) Modifying the IPN data before verification — send the exact POST body received, unmodified. (4) Using the wrong content-type — must be application/x-www-form-urlencoded. (5) Encoding issues — use the raw body bytes, not JSON-parsed values.
